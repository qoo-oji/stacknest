# StackNest の参照ファイル（.stacknestbook）— 版 1

**日本語** | [English](book-reference-format.en.md)

外部ビューアの作者向けの文書です。StackNest が対応した外部ビューアへ本を渡すときの、対応の宣言・参照ファイルの形式・API の約束を書きます。

## 流れ

1. 利用者が StackNest で「StackNest と読書位置を同期する（対応アプリのみ）」を ON にし、画像の本を外部ビューアで開く設定にする。
2. StackNest は、そのビューアが `Info.plist` で対応を宣言しているときだけ（[対応の宣言](#対応の宣言)）、本のファイルの代わりに **参照ファイル**（拡張子 `.stacknestbook`）を書き、外部ビューアで開く。開くビューアは、アーカイブ・フォルダ・画像の本ではそれぞれの種類の指定、PDF（ローカル・リモートとも）とリモートの画像だけの EPUB では「アーカイブ」の指定（ローカルの EPUB は参照ファイルを使わず、従来どおりファイルで開く）。
3. ビューアは参照ファイルに書かれた API から、ページを 1 枚ずつ取って表示し、読み進めたページを書き戻す。要求にはビューアの名乗りを付ける（[名乗りのヘッダ](#名乗りのヘッダ)）。
4. StackNest は参照ファイルを渡してから一定時間後（既定 15 秒）に一度だけ、そのトークンが使われたかを確かめる（[読まれたかの確認](#読まれたかの確認)）。

## 対応の宣言

**この宣言は必須です。** 対応するビューアは、自分の `Contents/Info.plist` に次のキーを置いてください。

```xml
<key>StackNestViewerSupport</key>
<dict>
  <key>referenceFormatVersions</key>
  <array><integer>1</integer></array>
</dict>
```

- `referenceFormatVersions` には、読める参照ファイルの版を整数で並べます。StackNest は自分が書ける版（今は `1`）との**共通の最大の版**を選び、参照ファイルの `version` に書きます。たとえば `[1, 2]` と宣言したビューアには、StackNest が版 2 を書けるようになれば版 2 で、それまでは版 1 で書きます。
- StackNest は渡す前に、そのビューアの `Info.plist` を直接読みます（LaunchServices の登録やキャッシュには頼りません）。次のどれかなら「未対応」として、トークンを出さず参照ファイルも作らず、従来どおり本を渡します（ローカルの本はファイルのまま、リモートの本は StackNest の内蔵ビューアで開きます）。
  - キーが無い、`dict` でない、`referenceFormatVersions` が配列でない
  - 共通の版が無い
- 配列の中の整数でない要素（真偽値・小数・文字列）と 0 以下の値は無視します。
- 参照ファイルの型を開けるという宣言（`CFBundleDocumentTypes`・UTType）は、**対応の判定には使いません**。どんなファイルでも開けると宣言しているアプリを、対応アプリと取り違えないためです。

## 型

| 項目 | 値 |
|---|---|
| 拡張子 | `stacknestbook` |
| UTType | `app.shelfsmith.stacknest.book-reference`（`public.json` に適合。StackNest が宣言する） |

参照ファイルを書類として受け付けるには、この型を `Info.plist` の `UTImportedTypeDeclarations` で取り込み宣言し、`CFBundleDocumentTypes` で書類の種類として受け付けてください（`application(_:open:)` に届きます）。StackNest は `open` でアプリを名指しして渡すので、順位（`LSHandlerRank`）は `Alternate` で足ります。これは Finder での見え方とファイルの受け取りのためで、対応の判定には上の「対応の宣言」が要ります。

## 中身（UTF-8 の JSON）

```json
{
  "format": "stacknest-book-reference",
  "version": 1,
  "title": "本の題名",
  "book": "http://192.168.1.10:51234/api/v1/libraries/<lib-uuid>/books/<id>",
  "token": "<本専用のトークン>",
  "expiresAt": "2026-10-31T12:00:00Z",
  "pageCount": 180,
  "direction": "rtl",
  "startPage": 41
}
```

| 項目 | 型 | 意味 |
|---|---|---|
| `format` | 文字列 | 常に `stacknest-book-reference`。違えば開かない |
| `version` | 整数 | 形式の版。宣言した版のうち StackNest が選んだもの（この文書は `1`）。**読めない値なら開かない** |
| `title` | 文字列 | 本の題名（窓の題名などに使う） |
| `book` | 文字列（URL） | 本の API の基点。下の 4 つの API はこれに続ける |
| `token` | 文字列 | その本専用の読み取りトークン。`Authorization: Bearer <token>` で渡す |
| `expiresAt` | 文字列（ISO 8601・UTC） | トークンの有効期限（発行から 30 日） |
| `pageCount` | 整数 | 開いた時点のページ数（正は `manifest`） |
| `direction` | `"rtl"` / `"ltr"` | 開いた時点の読む方向（正は `manifest`） |
| `startPage` | 整数（0 始まり） | 開いた時点の読書位置。ここから開く |

- 知らない項目は読み飛ばしてください（後の版で項目が増えても開けるように）。
- ローカルの書庫の本では `book` が `http://127.0.0.1:<port>/api/v1/libraries/<lib>/books/<id>` になります（その Mac の中だけで待ち受ける口）。
- **リモートの書庫の本も、`book` は `http://127.0.0.1:<port>/api/v1/relay/<relayID>` になります**（試用）。StackNest がこの口で受けた要求を、リモートのサーバへ中継します。実測では、サンドボックスのビューアが `NSAllowsLocalNetworking` の下で届くのは 127.0.0.1 とプライベートのアドレスまでで、Tailscale のアドレス（100.64.0.0/10）や公開のアドレスへの平文の HTTP は App Transport Security に止められます。そのため StackNest がリモートの本を中継し、ビューアはいつも手元の 127.0.0.1 につなげば済むようにしています。下の 4 つの API はローカルの本と同じで、ビューアは `book` の形を見分ける必要はありません。リモートのサーバの鍵はビューアには渡りません（参照ファイルの `token` は中継用の鍵で、`expiresAt` は発行から 30 日とリモートの鍵の期限の早い方です）。
- この口は StackNest が起動していて設定が ON のあいだだけ動き、ポートも変わることがあります。接続を拒まれたら、「StackNest から開き直してください」と表示してください。StackNest を終了すると中継は消えるので、その後の要求は **401** になります（中継の期限が切れたときも同じです。「StackNest から開き直してください」と表示してください）。中継の取り次ぎでリモートのサーバに届かない・応答が大きすぎる・リダイレクトされたときは **502** です。中継の `progress` に 64 KiB を超える本文を送ると **413** で、リモートには取り次ぎません。リモートの応答（403・404 や `X-Library-Locked` を含む）はそのまま返します。リモートが中継を **401・403** で断ったら（パスワードの変更・接続の取り消しなど）、StackNest はその応答を返したうえで中継を閉じるので、以後の要求はキャッシュにあるページも含めて **401** になります（「StackNest から開き直してください」と表示してください）。
- 中継のとき、`maxw` を付けない（または `maxw=1600` の）`pages/{n}` は、StackNest の内蔵ビューアと同じ画像を返します。幅が 1600 ピクセルを超えるページは、長い辺が 1600 ピクセル以内になるように縮み、JPEG に変換されます（PNG・WebP のページも。原寸・元の形式は届きません。`Content-Type` を見てください）。StackNest は中継したページを手元のキャッシュに入れて内蔵ビューアと分け合い、本を渡した後は、StackNest の設定に従って、読んでいるあたりのページ（設定によっては全ページ）を裏で先読みします。この応答には `ETag` が付かないので、`If-None-Match` を使わずに取り直してください（キャッシュから返すので速い）。ほかの `maxw` は今までどおりリモートへ取り次ぎます。

## API

すべて `Authorization: Bearer <token>` と、下の[名乗りのヘッダ](#名乗りのヘッダ)を付けます。

| 要求 | 応答 |
|---|---|
| `GET {book}/manifest` | `{"pageCount": 180, "direction": "rtl", "format": "archive", "etag": "…"}`（ほかの項目は読み飛ばす）。`format` は参考情報で、値は `archive`・`folder`・`image`・`text`（PDF と画像だけの EPUB）。どの値でも `pages/{n}` で同じように読んでください |
| `GET {book}/pages/{n}` | `n` 番目（0 始まり）のページの画像（JPEG・PNG・WebP など。`Content-Type` を見る）。`?maxw=<幅>` で縮小を頼める。`ETag` が付いているときは `If-None-Match` で 304 を受けられる（中継のときは付かないことがある） |
| `GET {book}/cover` | 表紙の画像（`?maxw=` 可） |
| `POST {book}/progress` | 本文 `{"page": n}`（0 始まり）で読書位置を書き戻す。200 |

- このトークンで使えるのは上の 4 つだけです。ほかの URL・ほかの本は **403** です。
- 自分の本への **403** でも、ヘッダ `X-Library-Locked: 1` が付いているときは、参照ファイルを作った後に書庫のロックが変わった（パスワードを変えた、または施錠した）ことを表します。「StackNest で書庫を解錠し、StackNest から開き直してください」と表示してください。
- **401** はトークンの期限切れ（または取り消し）です。「StackNest から開き直してください」と表示してください。
- **404** は本が見つからない（書庫から消えた、サーバが書庫を閉じた）ことを表します。`pages/{n}` では範囲外のページ番号も **404** です。
- `pages/{n}` でページを描画できないときは **500**、`progress` に負のページを送ると **400** です。

## 名乗りのヘッダ

**このヘッダは必須です。** 本の API を呼ぶたびに、次のヘッダを付けてください。

```
X-StackNest-Viewer: <bundle id>/<ビューアの版>; format=<参照ファイルの版>
```

例: `X-StackNest-Viewer: com.example.viewer/1.80; format=1`

- `<ビューアの版>` は `CFBundleShortVersionString` などの、利用者に見える版です。`format=` には、開いた参照ファイルの `version` を書きます。
- StackNest はヘッダが無くても要求を拒みません。トークンが初めて使われたときに、その日時とこのヘッダの値を一度だけ記録します（印字できる ASCII だけを残し、200 文字で切ります）。記録は、設定の「外部ビューア」の節で、どのビューアの対応を確認できたか（日時と版）を示すのに使います。

## 読まれたかの確認

- StackNest は参照ファイルを渡してから一定時間後（既定 15 秒）に一度だけ、そのトークンが使われたかを確かめます。ローカルの本も中継するリモートの本も、手元の 127.0.0.1 の口の記録で確かめます（中継を使わずにリモートのサーバへ直接つなぐ形でだけ、トークンを発行した接続から `GET /api/v1/viewer-tokens/{tokenID}`（状態の API）で確かめます）。
- 中継の鍵の「使われた」は、ビューアが有効な中継の鍵で 127.0.0.1 の口に**届いた**ことを指します（ページを読み込めたことではありません。リモートが 502 でも、`manifest` の要求が届けば記録されます）。中継の鍵の記録は実際の書庫・本を持たず、見張り用の値（書庫 `"relay"`・本 0）を持ちます（ビューアが気にする必要はありません）。
- まだ使われていなければ、StackNest は「〈アプリ名〉が本を読み込んでいません」と知らせ、従来の開き方（ローカルの本はファイルのまま、リモートの本は内蔵ビューア）で開くボタンを出します。トークンは取り消さないので、ビューアが遅れて読み始めても動きます。
- 参照ファイルを受け取ったら、まず `manifest` を取ってください（開いたことが早く伝わります）。

## ビューアへのお願い

- `startPage` から開いてください。ビューア自身の読書位置の記録があっても、参照ファイルの `startPage` を優先してください。
- ページを移るたびに書き戻すのではなく、数秒まとめて `progress` に送ってください。閉じるときにも送ってください。
- すべての要求に[名乗りのヘッダ](#名乗りのヘッダ)を付けてください。
- トークンは秘密です。ログに出さず、ほかへ送らないでください（詳しくは下の「セキュリティ上の注意」）。
- 通信は HTTP です（LAN か Tailscale での利用を前提にしています）。App Transport Security で 127.0.0.1 と LAN への平文 HTTP を許可し、App Sandbox を使うならネットワーク（クライアント）の権限を付けてください。

## セキュリティ上の注意

- トークンは参照ファイルの中に**平文**で入っています。StackNest は参照ファイルを権限 600（本人だけ読める）、置き場のディレクトリを 700 で書きます。有効期限は 30 日です。ビューアはトークンをほかの場所へ写さず、ログにも出さないでください。
- `book` の基点が LAN 上の `http://` のアドレスのとき、トークンは暗号化されずに流れます。StackNest は HTTP だけを提供します。素の LAN では暗号化されないので、Tailscale 越しの StackNest のリモート接続を使うと通信が暗号化されます。リモートの本を中継するとき（試用中の既定）は、ビューアとの通信は 127.0.0.1 の中だけで、StackNest とリモートのサーバの間は StackNest のリモート接続と同じ道を通ります。
- 基点には IPv6 のアドレスが入ることがあります（例: `http://[fe80::1%25en0]:51234/…`）。ビューアは角括弧で囲まれたホスト（ゾーン ID を含む）を解釈できるようにしてください。
- トークンは参照ファイルの `book` が指すオリジン（スキーム・ホスト・ポート）にだけ送ってください。リダイレクト先や別のホストへ付けて送らないでください。
- 使われたかの照会（`GET /api/v1/viewer-tokens/{tokenID}`）は、トークンを発行した主体だけが読めます。ただし共有サーバを固定トークン（グラント無し）で動かしているときは主体を区別できないので、同じトークンを持つ接続はどれも、そのトークンで発行した本専用トークンの使用の状況（日時と名乗りだけ）を読めます。127.0.0.1 の口でも、ローカルコントロールが ON なら CLI・MCP のトークンが、App の出したトークンの状況を読めます。どちらも名乗りのヘッダの値が見えるだけで、本の中身やトークンは出ません。

## 版の扱い

| 版 | 内容 |
|---|---|
| 1 | この文書（Phase G60 で導入） |

ビューアは読める版を `referenceFormatVersions` で宣言し、StackNest は共通の最大の版で書きます。後の版で項目が増えても、版 1 だけを宣言したビューアには版 1 で書きます。

API の詳しい仕様は StackNest のサーバが配る `/openapi.yaml`（`/docs`）にあります。
